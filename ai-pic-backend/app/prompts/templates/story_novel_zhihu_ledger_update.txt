Rules:
- The ledger must be **incrementally updated** from previous_ledger; do not rewrite already established facts out of thin air.
- Keep list lengths under control: `facts` / `open_threads` / `resolved_threads` max 25 each; `timeline` max 30 entries; each `events` list max 8 items.
- Time / location anchors: extract them from the text whenever possible; if the text is not explicit, use low-assumption anchors such as "that night / the next day / a few days later" and coarse-grained locations such as "office / home / hospital / street"; avoid contradicting the chapter text.
- Information-acquisition events: record the first-time points where someone learns a name / identity / key fact in `info_acquisition_events`, and make `how` explicit; avoid duplicate entries for the same event (merge / deduplicate when needed).
- `chapter_summary` must faithfully reflect what happened in this chapter and the character changes, rather than speaking in vague generalities.
- `chapter_cliffhanger` must continue the suspense created by this chapter's ending and must not spoil the entirety of the next chapter.
- Output JSON only; real newline characters are forbidden inside JSON strings. If you need a line break, write it as \n.
