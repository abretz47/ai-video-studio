You will generate an executable list of "key beats" for one chapter of a Zhihu-style long-form story for later writing.

Please output **strict JSON** (no code fences, no explanations) in the following structure:
{
  "key_beats": ["List 5-9 key beats in chronological order (short phrases)"]
}

[Story information]
{{ story | tojson }}

[Overall outline (plan)]
{{ plan | tojson }}

{{ ledger | tojson }}

[Previous chapter ending excerpt (previous_tail)]
{{ previous_tail }}

[Previous chapter cliffhanger (previous_cliffhanger)]
{{ previous_cliffhanger }}

[Current chapter plan]

Chapter title: {{ chapter.title }}
Target word count: {{ chapter.target_words }}
Chapter goal: {{ chapter.chapter_goal }}
End-of-chapter cliffhanger hint: {{ chapter.cliffhanger_hint }}

[Generated running summary]
{{ running_summary }}

Rules:
- `key_beats.length` must be between 5 and 9
- Every beat must be specific, executable, and contain action / conflict / information progression. Avoid summary-style narration.
- Strictly follow the facts / character relationships / timeline in the ledger; do not create contradictions.
- You must naturally continue from previous_tail (if it is empty, begin from this chapter's opening)
- If previous_cliffhanger is not empty, the first beat must directly respond to / continue that cliffhanger (either continue the scene or immediately explain what happened after the cliffhanger).
- The final beat should lead into cliffhanger_hint (it does not need to include the exact cliffhanger line, but the setup must be sufficient).
- If a new character name appears in beats for the first time (it did not previously appear in previous_tail / running_summary / ledger.characters), that beat must specify *how the name is obtained* (self-introduction, someone else's introduction, badge/nameplate, phone note, etc.).
- Output JSON only; real newline characters are forbidden inside JSON strings. If you need a line break, write it as \n
